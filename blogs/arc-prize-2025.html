ARC Prize 2025: Solving Puzzles With No Pretraining

ARC Prize 2025 · 4 min read

ARC Prize 2025 ran on ARC-AGI-2. My entry finished 124 of 1,455 (top 9%). The solver was adapted from a public CompressARC-based notebook that trains a small network from scratch on each puzzle. The hard part was throughput, not the model.

No pretraining, one network per puzzle

Most strong ARC entries lean on scale. This one uses no pretraining, no external data and no search. For each puzzle it starts a small network from random weights, trains it on that puzzle's train pairs only, and predicts the test output.

CompressARC (Liao and Pari, 2025) frames this as minimum-description-length compression. A tiny network of about 76K parameters is fit per task with a VAE-style loss, so gradient descent does the reasoning.

12 hours is the real constraint

The competition runs a Kaggle notebook offline, within 12 hours, scored pass@2. CompressARC's original setup solved puzzles in series, underused a single GPU and, as the notebook admits, "blew past the time budget". A per-puzzle method is parallel only if you schedule it that way.

The notebook is a scheduler

The network internals live in imported modules from the compressarc dataset. The notebook calls solve_task.solve_task(...) once per puzzle and handles memory probing, parallelism, timing and submission.json. One model-side change was rewriting layers.direction_share(), for a 5 to 10% speedup.

Probe, then pack

  • Memory probe. Run 2 steps of every puzzle to measure its GPU memory.
  • Timing probe. Run 10 steps at the chosen parallelism to measure seconds per step.
  • Main run. Pick the largest step budget that fits 12 hours. For 120 puzzles the plan estimates about 2300 steps each.

The scheduler reads free GPU memory, subtracts a 6 GB buffer, and launches puzzles while memory and CPU count allow. A 600 s timeout kills runaway puzzles, and a global end-time check stops the run before the deadline.

Limits I won't dress up

  • The notebook prints no score. For calibration, CompressARC reports about 20% on ARC-AGI-1 eval and about 4% on ARC-AGI-2.
  • The active cell is more conservative than the plan. It runs a 5-step estimate and a 20-step main run with a flat 1 GB per task, far below the 2300-step target. It is safe, but it costs fit quality.
  • Augmentation and the two predictions come from the imported solve_task, not from cells I wrote, so I describe them only at the method level.

What I'd do differently

  • Run the full probe-then-pack plan. Quality scales with steps per puzzle, and the fallback used a tiny fraction of the plan.
  • Replace the flat 1 GB assumption with the measured memory probe.
  • Save the score inside the notebook, so the run can be judged from its own output.
  • Treat packing as the lever. The ceiling is memory-limited parallelism inside 12 hours.
